    SayQL documentation

    Everything you need to install SayQL, connect your databases, pick an AI and turn plain English into SQL you can trust.

    InstallDownload and open SayQL on macOS, Windows or Linux. Choose your AIClaude, OpenAI, Gemini, a local model and more. Ask in EnglishQuestions, follow-ups, fixes and Improve.

    Install

    SayQL is a desktop app, downloaded straight from GitHub. There's no account and no app store.

    Get the latest version from Releases and pick the file for your computer:

    Your computerDownload
    Mac with Apple silicon (M1, M2, M3, M4)SayQL_x.y.z_aarch64.dmg
    Mac with an Intel processorSayQL_x.y.z_x64.dmg
    WindowsSayQL_x.y.z_x64-setup.exe (or the .msi)
    Linux.AppImage (any distribution), .deb (Debian, Ubuntu) or .rpm (Fedora, RHEL)

    Not sure which Mac you have? Apple menu → About This Mac: "Chip: Apple M…" means Apple silicon; "Processor: Intel" means Intel. Ignore the .tar.gz and .sig files: they're used by automatic updates.

    First launch

    Early-access builds aren't code-signed with Apple or Microsoft yet, so your computer asks you to confirm the first launch. You only do this once.

    1. macOS: open the .dmg and drag SayQL into Applications. Open it from Applications and click Done on the warning. Then open System Settings → Privacy & Security, scroll down, click Open Anyway next to "SayQL was blocked", and confirm.
    2. Windows: run the installer. On "Windows protected your PC", click More info, then Run anyway.
    3. Linux: make the AppImage executable (chmod +x SayQL_*.AppImage) and run it, or install the .deb or .rpm with your package manager.

    The setup guide

    On first launch, SayQL walks you through four short steps: a welcome, choosing an AI, choosing a database (the built-in demo or your own), and a first question that writes and runs SQL in front of you. Every step can be skipped. To see it again, open Settings and click Show the setup guide again under About.

    Choose your AI

    SayQL writes SQL with the AI provider you pick, using your own API key. Change it any time in Settings (the gear, top right).

    ProviderWhat you need
    Anthropic Claude (recommended)An API key from the Claude Console.
    OpenAIAn API key from the OpenAI platform.
    Google GeminiAn API key from Google AI Studio.
    OpenRouterOne key from OpenRouter for models from many labs.
    Mistral, Groq, DeepSeekAn API key from that provider's console.
    Ollama (on your computer)Ollama installed and running, with a model pulled. No key.
    LM Studio (on your computer)LM Studio with its local server started. No key.
    Other (OpenAI-compatible)The base URL of any server with an OpenAI-compatible API (Azure, vLLM, LiteLLM, a company gateway), and a key if it needs one.

    Set it up

    1. Open Settings and choose the AI provider.
    2. Paste the API key. It's stored in your system keychain, never in a file.
    3. For providers other than Claude, click Load models. This also checks the key and address. Pick a model, then Save.

    SayQL uses two models: a fast one that drafts SQL as you type, and a stronger one for fixing a rejected query and for Improve. With Claude these default to Haiku and Opus. With other providers, leave the second empty to use the same model for both.

    Local models

    With Ollama or LM Studio, your questions and schema never leave your computer. For Ollama, install it, pull a model (for example ollama pull llama3.2) and keep it running. SayQL connects to http://localhost:11434/v1 by default. LM Studio's local server is at http://localhost:1234/v1. Change the base URL in Settings if yours runs elsewhere.

    Claude API keys and workspaces. If your key isn't tied to a workspace, add the workspace's ID (it starts with wrkspc_) in Settings. Use the ID from the Claude Console, not the workspace's name.

    Connect a database

    SayQL connects straight from your computer to your database. There's no SayQL server in between.

    Click New connection in the top bar, pick the type, fill in the details and click Test, then Save. Passwords are stored in your system keychain.

    TypeDefault portNotes
    PostgreSQL5432Turn on Require SSL for hosted databases.
    MySQL / MariaDB3306Turn on Require SSL if your server requires it.
    SQL Server / Azure SQL1433Azure SQL needs Encrypt connection, which is on by default.
    SQLite—Pick the database file. A file is one database.

    Every database on the server

    For server databases, the navigator lists every database your login can open, under Databases. Click one to open it. The Database field in the connection only sets which one opens first; leave it empty to use the server's default.

    SQL Server tips

    • Internal SQL Servers often use a self-signed certificate. If connecting fails with a certificate error, turn on Trust server certificate, but only for servers you know.
    • If the login works in other tools but not here, set the database to master (or leave it empty) and pick your database from the navigator.

    The demo database

    SayQL comes with Demo store, a small SQLite shop with customers, orders and products, so you can try everything without connecting anything. Delete it with a right-click if you don't need it.

    Ask in plain English

    Type what you need in the Ask box above the editor. The SQL appears in the editor as you type.

    • Run it: press ↵ in the Ask box, or ⌘↵ / Ctrl+↵ anywhere. ⇧↵ adds a new line and esc clears the question.
    • Instant answers: simple requests like "show customers" or "how many orders" are answered on your computer straight away, without calling the AI.
    • Follow-ups: after running a query, say what to change: "only Canada", "remove the middle name", "sort by date". SayQL edits the query you have, and shows Building on your last query. Click New query to start fresh.

    Point it at the right tables

    Click a table in the navigator to give it to the AI as context. ⌘-click (or Ctrl-click) adds more, and ⇧-click picks a range. Picked tables show as a pill in the Ask box. Click the eye on the pill to hide them from the AI without losing the selection. This helps most in large databases.

    Fix and Improve

    • Fix: when the database rejects a query SayQL wrote, the stronger model reads the error, corrects the SQL and runs it again, once. If that fails too, you decide what to do next.
    • Improve: click Improve above the editor to have the stronger model review the query against your question (joins, filters, dates, grouping, NULLs and the columns shown) and return the best version of it. If it's already right, it comes back unchanged.

    Run queries safely

    SayQL is built so that pointing it at a production database isn't scary.

    Read-only by default. SayQL checks every statement before it runs. Anything that could change data or structure (INSERT, UPDATE, DELETE, DDL and so on) stops and shows a confirmation first.

    • Reads also run inside a read-only transaction (PostgreSQL and MySQL) or on a read-only connection (SQLite), so the database itself refuses writes. SQL Server has no read-only mode, so reads run in a transaction that's always rolled back. For production SQL Servers, use a login that can only read (db_datareader).
    • Results show up to 5,000 rows. Use LIMIT / TOP or filters for more focused results. Copy as CSV copies the rows shown.

    Tabs and saved scripts

    • ⌘T opens a new SQL tab on the current database. Each tab keeps its own question, SQL and follow-up history.
    • ⌘S saves a tab as a script. Saved scripts appear under Saved scripts in the navigator and reopen on the database they were written for.
    • Closing a tab with unsaved SQL asks whether to save it first.

    Navigator and right-click

    The panel on the left lists connections, databases, tables, views and columns, like DBeaver.

    • Double-click a table to view its first 100 rows.
    • Type in Filter tables and columns to find something in a large schema.
    • Right-click anything for its actions:
    Right-click onActions
    ConnectionConnect, New SQL tab, Refresh, Edit connection, Copy name, Delete connection
    DatabaseOpen database, New SQL tab, Refresh, Copy name
    Table or viewView data, Count rows, Generate SQL (SELECT; and INSERT, UPDATE, DELETE for tables), Add to AI context, Copy name, Copy as SQL reference, Refresh
    ColumnCopy name, Copy with table name
    Saved scriptOpen, Copy name, Delete script

    Generated INSERT, UPDATE and DELETE open in a new tab without running. Their WHERE matches no rows until you fill it in, and running them still asks for confirmation.

    Use SayQL from AI apps (MCP)

    SayQL includes an MCP server, so AI assistants like Claude and Cursor can query your databases through the connections you saved in SayQL.

    Not in the v0.1.0 downloads yet. The MCP server program isn't bundled with the first release. It's coming in an upcoming update, and Settings will show you when it's available.

    The assistant gets four tools: list connections, list databases, describe the schema, and run a read-only query. The same read-only rules apply. Results default to 100 rows, at most 1,000. Database passwords are never shared with the assistant, but query results are sent to it.

    Set it up

    Open Settings → Use SayQL from AI apps (MCP). It shows the exact command and config for your install:

    • Claude Code: run the claude mcp add command it shows, in a terminal.
    • Claude Desktop: merge the JSON it shows into claude_desktop_config.json and restart Claude Desktop.
    • Cursor and other MCP apps: add a stdio server that runs the sayql-mcp path shown in Settings.

    Updates

    SayQL checks for a new version when it starts. When one is available, an Update to x.y.z button appears in the status bar at the bottom. Click it to download, install and restart. Every update is signed, and SayQL refuses any update whose signature doesn't match.

    On macOS, after an update the system may ask once whether SayQL can use its saved passwords in your keychain. Click Always Allow. All of SayQL's passwords and keys share one keychain item, so it's one prompt.

    Privacy and data

    SayQL has no account, no server of its own and no telemetry. It sends data only to services you configure, and only when you use them:

    WhenWhat's sentTo
    You connect or run a queryYour login and your SQLYour database
    You ask in plain EnglishYour question; table and column names, types and keys; the previous query for follow-upsYour AI provider
    A query fails and SayQL fixes itThe query and the database's errorYour AI provider
    An AI app uses SayQL over MCPThe schemas and query results it asks forThat AI app

    The rows in your tables are never sent to an AI provider by the Ask box. With a local model, nothing leaves your computer. Read the full privacy notice.

    Troubleshooting

    macOS says "Apple could not verify SayQL"

    That's expected for early-access builds. Click Done, then open System Settings → Privacy & Security and click Open Anyway. If you trust the download, this also works in Terminal: xattr -dr com.apple.quarantine /Applications/SayQL.app

    Windows shows "Windows protected your PC"

    Click More info, then Run anyway. You only need to do this once per installer.

    macOS keeps asking for my keychain password

    macOS asks once after each update of an unsigned build, because the app's signature changed. Click Always Allow (not just Allow) and it won't ask again until the next update.

    "Your API key was rejected"

    The key is wrong, revoked or out of credit. Paste it again in Settings. For non-Claude providers, Load models tells you straight away whether the key works.

    "This API key isn't tied to a workspace"

    Add your Claude workspace's ID (starting with wrkspc_) in Settings → Workspace ID. Use the ID, not the workspace's name.

    "Could not reach Ollama" (or LM Studio)

    The local server isn't running. Start Ollama (or run ollama serve), or start LM Studio's local server, then try again. Check the base URL in Settings if it runs on another port or computer.

    SQL Server: certificate errors

    The server uses a certificate your computer doesn't trust, which is common for internal servers. SQL Server always encrypts the login, so this can happen even with Encrypt connection off. Turn on Trust server certificate for servers you know.

    SQL Server: "Login failed" (error 18456)

    The server was reached but didn't accept the user and password. Check them, or try them in another SQL client. It can also mean the login is disabled, or the server only allows Windows or Entra sign-in.

    SQL Server: "Cannot open database" (error 4060)

    The login works but can't open the database you named. Check the name, or leave Database empty and pick one from the navigator.

    My results stop at 5,000 rows

    SayQL shows up to 5,000 rows per query to keep the app fast. Add a filter, LIMIT or TOP, or aggregate the data you need.
