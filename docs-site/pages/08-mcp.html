SayQL includes an MCP server, so AI assistants like Claude and Cursor can query your databases through the connections you saved in SayQL.

On Linux, use the .deb or .rpm for MCP. The AppImage opens from a new folder each time, so the path you give your AI app would stop working.

The assistant can list connections, list databases, describe the schema, and run a read-only query. The same read-only rules apply. Database passwords are never shared with the assistant. What it gets back from a query is up to you, per connection (below): by default counts and summaries, not your rows.

It can also list your saved scripts, and, on connections where you allow all rows, export a read-only query to a CSV in your Downloads folder (up to 100,000 rows). Exported rows aren't sent to the assistant, only the file path, but it could open the file, so export follows the same setting.

Three more tools hand work to you in SayQL instead of doing it:

  • Add connection opens SayQL's New connection dialog with the details filled in. You type the password in SayQL, test and save.
  • Open query opens SQL in a new SayQL tab, unrun. You review it and click Run; SayQL asks before anything that changes data, and the results stay in SayQL.
  • Open script opens one of your saved scripts, unrun.

The schema the assistant gets includes the database notes you saved, so it knows what codes mean and how tables relate. Columns you marked never send in a connection's agent settings stay private over MCP too: a query that names one is refused, and their values are withheld when a query returns them anyway.

Table usage

After each table, describe_schema says how much it is used, from the database's own statistics, so the assistant can tell a live table from an abandoned one, for example usage: 12.3k reads, 0 writes, last write 2026-03-12. One line above the tables gives the period the figures cover ("since 2026-01-01", or "since the server started on …"): the counters reset when the server restarts or fails over, and differ on each replica. They are counts and dates, never row values.

  • PostgreSQL: reads (sequential and index scans), written rows and live rows from pg_stat_user_tables, and when the table was last analyzed; the period starts when the database's statistics were reset, else when the server started.
  • SQL Server: seeks, scans and lookups as reads, updates as writes, and the last read and write, from the index usage statistics since the server started. A table with no entry wasn't used in that time.
  • MySQL and MariaDB: read and write counts from performance_schema when it's on and readable, and the last write time MySQL keeps.
  • SQLite keeps no such statistics, so nothing is shown.

It's one extra query per describe_schema, stopped after 5 seconds. If the database user can't read the statistics (or they're turned off), one line says usage statistics are unavailable.

Notes suggested by AI apps

When an assistant learns a lasting fact about a database (a table that's no longer used and what replaced it, what a status code means, how two tables relate), it can call suggest_note with the note (up to 300 characters) and its evidence (up to 600), such as "no references in api/ since commit a1b2c3; usage: 0 writes since 2026-01-01". Notes describe the database, never the data in it: a note or evidence that looks like a value from your rows (an email, a phone number, a long id) is refused.

A suggestion isn't a note until you accept it. A database's suggestions show under Notes → Suggested by AI apps in the navigator, with a count; all of them are in Settings → AI apps (MCP) → Suggested notes. Each shows the app, the note and the evidence, with Accept (it's saved like a note you wrote, so the Ask box, agent mode and every AI app see it from then on) and Dismiss. Up to 50 suggestions wait per connection, a note already saved or suggested is refused, and each suggestion is in the agent activity log.

Passwords and writes never go through MCP. SayQL brings its window to the front and marks what came from an AI app, e.g. From Claude (MCP).

What AI apps may see

In Settings → AI apps (MCP), choose for each saved connection what an AI app gets back from a query:

  • Nothing: only how many rows a query returned, and its column names.
  • Counts and summaries (the default): the row count and, per column, its type, nulls, distinct values, and min and max for numbers and dates. No row values. The assistant answers with queries whose numbers answer the question, and can open SQL in SayQL when you want to see the rows yourself.
  • Rows, masked: rows, with likely personal data (emails, phones, names, IDs) replaced by tokens such as ‹email-1›. This is best effort: a free-text column can hold anything.
  • All rows: rows as they are, in pages of 100 by default and at most 1,000, and CSV export. For data you're happy to share with that app.

Columns marked never send stay out at every level. Below All rows, values that a database error quotes (a duplicate key, a failed conversion) are masked too.

Agent activity and blocking an app

Below that, Agent activity lists what AI apps ran through SayQL on this computer: when, which app, the connection, the SQL, and whether it ran (with the row count) or was refused and why. It keeps the SQL and counts, never rows, in a file in SayQL's folder; Clear the log deletes it.

Each app SayQL has seen is listed with a Block button. A blocked app is refused everything until you click Allow. Apps give their own name when they connect, so a block stops an app like Cursor, not software on your computer that pretends to be another app.

Set it up

Open Settings → AI apps (MCP). It shows the exact command and config for your install:

  • Claude Code: run the claude mcp add command it shows, in a terminal.
  • Claude Desktop: merge the JSON it shows into claude_desktop_config.json and restart Claude Desktop.
  • Cursor and other MCP apps: add a stdio server that runs the sayql-mcp path from the Claude Desktop config shown in Settings.
