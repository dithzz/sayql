SayQL writes SQL with the AI provider you pick, using your own API key. Change it any time in Settings (the gear, top right). Back or esc returns to your work.

Set it up

  1. Open Settings → AI provider and pick a Provider.
  2. Paste the API key. It's stored in your system keychain, never in a file.
  3. For providers other than Claude, click Load models. This also checks the key and address. Pick a model, then Save.

SayQL uses two models: Model while typing, a fast one that drafts SQL as you type, and Model for fixes and improvements, a stronger one for fixing a rejected query and for Improve. With Claude these default to Haiku and Opus. With other providers, leave the second empty to use the same model for both.

The status bar shows the models in use, or AI off — set up an AI provider in Settings when none is set up.

What your AI provider gets

From the Ask box: your question, table and column names (with types, keys, enum values and row estimates), your database notes, the SQL you're working on for follow-ups, Explain, Fix and Improve, and a failed query's error with values from your rows masked. Data from your tables goes only if you turn on agent mode for a connection and allow it in its agent settings. The AI provider page in Settings says the same under Provider. See Privacy and data for everything SayQL sends.

Local models

With Ollama or LM Studio, your questions and schema never leave your computer. For Ollama, install it, pull a model (for example ollama pull llama3.2) and keep it running. SayQL connects to http://localhost:11434/v1 by default. LM Studio's local server is at http://localhost:1234/v1. Change the base URL in Settings if yours runs elsewhere.

Claude API keys and workspaces. If your key isn't tied to a workspace, add the workspace's ID (it starts with wrkspc_) in Settings. Use the ID from the Claude Console, not the workspace's name.
